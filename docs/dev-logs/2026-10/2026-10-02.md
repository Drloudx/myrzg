# 2026-10-02 开发汇总

> 主题：新增评论功能（Cloudflare Pages Functions + D1 + Turnstile 预留）。本文档为方案落地，方案与实现说明见 [评论后端方案](../technical/COMMENTS_BACKEND.md)。

## 数据与解析

### 评论审核词表取自游戏词库，但只取高置信子集

- 来源是游戏聊天风控词库 `Config_decrypted/words.json`：**不是 JSON 对象，而是逗号分隔的单个字符串**，95,050 字符、去重后 **14,078 条**。
- 实测词表性质：中国互联网垃圾广告词库（赌博 / 壮阳药 / 迷药 / 成人 / 政治敏感 / 垃圾域名与手机号）。其中激素类只有 2 条（`促性腺激素`、`蛋白合成激素`），用户印象中的"激素表"实际是**壮阳/迷药类**为主（24 + 10 条）。
- **整表同步被否决，两条独立理由**：
  1. **误伤**：表内含大量日常词——`比例`、`真实`、`购买`、`买菜`、`我爸`、`炸鸡`、`善良`、`香港`、`港口`，以及 464 个单字词（含 `草`、`妈`、`爸`、`鸡`、`&`）。开场白"这里的比例不太对，真实伤害是 305%"会被全表命中。
  2. **性能**：Workers 免费版每次调用只有 10ms CPU。本地实测每条评论匹配耗时——**全表扫描 0.82ms / 筛后词表+首字索引 0.076ms / 类别正则 0.0040ms**。
- 最终形态：`src/config/commentBlocklist.js` 用**7 条类别正则**（赌博/色情/违禁药/违禁品/诈骗/引流/政治敏感），按低误伤写法逐个挑选（例如「赌」只收 `赌博/赌场/赌球/下注/博彩`，不收单字 `赌`，否则"别赌气"被拦），外加 2 条结构性规则（外链、HTML 标签）。
- `scripts/dev/sync-comment-blocklist.mjs` 是**只读校验**而非生成器：把类别正则套用到游戏词库上，报告每类命中数（22/19/32/4/1/6/9 条），并自检"正常评论零误伤、垃圾样本零漏检"。缺游戏配置目录时静默跳过，不参与 `npm run verify`。
- **中途纠正了一次自己的错误**：初版按印象逐词列举，校验脚本抓出 27 个游戏表里根本不存在的词（`私聊`、`刷单`、`加微信`、`洗钱`、`qvod`…）。改为按类别正则从游戏表实测导出后，词表与来源一致。

### D1 表结构

- 库 `myrzg-comments`，id `5f0d4c37-107f-4811-bc5e-768f73c51a3a`，region WNAM。`comments` + `rate_limits` 两张表，**只建 2 个索引**：写入按行计费（索引也算行），全局清理用的 `created_at` 索引经权衡后**刻意不建**——D1 读便宜（500 万行/天）、写贵（10 万行/天），而清理查询极少执行。
- `comments` 关键字段：`status`（1 显示 / 0 待审 / 2 已隐藏）、`token_hash`（浏览器自删令牌的 SHA-256）、`review_reason`（命中的审核类别）、`email_hash`（**绝不存明文邮箱**）、`ip_hash`（限流用）。
- 增量迁移（已对远端库执行）：`ALTER TABLE comments ADD COLUMN token_hash ...` → 再 `... review_reason ...`。

## UI 与交互

- `src/components/CommentsPanel.vue`：讨论区（列表 / 发表 / 自删），只在**物品详情**挂载。业务组件不进通用 UI 出口，`CommentsPanel` 随 `ItemDetailModal` 的 chunk 加载，`AdminCommentsView` 独立成 6.06 kB chunk。
- 遵守既定约束：三态用 `UiEmptyState`、视觉只取 `theme.css` 语义变量、正文 13.5px / 行高 1.6、零 `.dark-mode` 覆盖、评论正文按**纯文本**渲染（不解析 HTML）。
- `src/views/AdminCommentsView.vue`：管理页 `/#/admin/comments`，令牌登录（存本机 localStorage）、按状态筛选、**放行 / 转待审 / 隐藏 / 彻底删除**，并显示每条命中审核词表的**原因**，便于区分误伤与真垃圾。刻意不进导航面板（靠令牌保护，未配 `ADMIN_TOKEN` 时接口直接 404）。
- 挂载范围只做物品详情：首页就是物品图鉴、卡片点开极频繁，列表页挂载会产生大量无效请求。

## 架构与决策

### 评论方案与免费额度（官方文档核实）

- Cloudflare 免费版可支撑：Functions 10 万次/天、D1 读 500 万行/天 + 写 10 万行/天 + 存储 5 GB、Turnstile **完全免费且挑战次数不限**、静态资源请求免费不限量、无 egress 费用。
- **CPU 10ms 是硬约束**：实测 PBKDF2-SHA256 —— 10,000 次 2.5ms、100,000 次 18.7ms、**600,000 次（OWASP 现行推荐）104ms**。
- **决策：一期不做账号体系**。理由：① 免费版 CPU 上限让"自己存密码"只能压到安全推荐值的约 1/60；② 想安全就得引入托管认证（独立一期更合适）；③ 它解决不了真正的问题（防机器人靠 Turnstile + 限流，删评论管理员已能做），反而增加注册/登录/找回密码等管理工作；④ 存邮箱带来隐私保护义务。迁移余地已留（将来加 `users` 表 + `user_id` 外键即可，不用重建数据）。
- 用户自删走**浏览器令牌**：发表时自动下发并存 localStorage，用户无需记任何东西；换设备/清浏览器数据后需联系管理员。同设备令牌能删、跨设备不能——相比"设密码 + 忘密码 + 没救"是更优取舍。

### 三个实测出来的坑

1. **SPA 兜底会吃掉 API 请求**：`public/_redirects` 是 `/* /index.html 200`，实测线上 `/api/health` 返回 **200 + `text/html`**。已加 `/api/* /api/:splat 200` 放行规则（`_redirects` 不支持 `!` 取反，只能显式放行）。本地验证 `/api/health` 已返回 `application/json`，且 SPA 兜底仍正常。
2. **EdgeOne 不缓存 JSON**（连打三次对照实验）：`/ui/logo.webp` → `HIT`、`Age` 递增；`/data/parsed/items.json?same=1` → **`MISS`、`Age=0` 始终不变**，而源站已带 `immutable, max-age=31536000`。说明该域名按**文件类型**缓存，只缓存图片。评论接口是 JSON，天然不受影响；仍保留 `/api/*` 的 `no-store` 与 EdgeOne 规则建议作为防御。
3. **EdgeOne 回源确认**：控制台显示源站类型 `IP/域名`、源站配置 `myrzg.pages.dev` → 回源到 Cloudflare Pages，Functions 方案成立（若源站是静态存储桶则方案作废）。

## Bug 修复

- **蜜罐字段对用户可见**：初版只用 `left: -9999px` 移出视口，键盘 Tab 与屏幕阅读器仍会撞上这个"昵称（选填）"输入框。改为 `visibility: hidden` + `opacity: 0` + 尺寸归零 + `padding/border` 清零，并对意外聚焦做 `blur()`。刻意不用 `display:none`（部分机器人只跳过它）。由浏览器验证断言"蜜罐不可见"抓出。

- `node scripts/dev/sync-comment-blocklist.mjs` —— 类别覆盖正常、正常评论误伤 **0/7**、垃圾样本漏检 **0/5**。
- API 端到端（`wrangler pages dev` + 本地 D1，Python 脚本）：**22/22 通过** —— 错误文案可读（蜜罐 403 / 空内容 400 / 非法 page_key 400）、软删除（错令牌 403、正确令牌 200、删后从公开列表消失、重复删除幂等）、分页（hasMore / nextCursor / 倒序 / 第二页不重复 / limit 夹到 50）、**公开列表无 `token_hash`/`ip_hash`/`ua_hash` 泄漏**、XSS 原文存储并命中 HTML 规则进待审。
